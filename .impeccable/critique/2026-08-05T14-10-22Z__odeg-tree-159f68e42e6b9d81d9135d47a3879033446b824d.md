# VibeX 与 Codeg UI/产品对比评审

## 评审基线

- VibeX：当前工作区 `frontend/src`，结合本地设计规范、产品说明和浏览器实测。
- Codeg：固定提交 `159f68e42e6b9d81d9135d47a3879033446b824d`，避免与持续变化的主分支混比。
- 方法：Assessment A 独立源代码与截图评审；Assessment B 独立 detector 与浏览器实测；另加产品经理视角复核。

## 结论

VibeX 的设计北极星比 Codeg 更清晰：它不是“把所有 AI 能力集中到一个聊天应用”，而是面向专业开发者的本地工程驾驶舱。当前主要问题不在缺功能，而在产品入口、导航语义和视觉实现尚未完全服从这套定位。Codeg 的优势是首次启动、切换与恢复会话更直接；VibeX 的优势是项目、任务、Worktree、检查、审批与交付链路更完整。

综合 Nielsen 启发式评分：VibeX 25/40，Codeg 32/40。分差主要来自 Codeg 更持续的上下文、更直接的会话入口和更强的可识别导航；不是因为 Codeg 的视觉语言更高级。

## 最高优先级问题

### P1 — 键盘焦点、语义和可访问名称

- 全局样式对含关闭图标的按钮移除 `focus` 与 `focus-visible` 轮廓且没有等价替代。
- Project Card 使用带 `onClick` 的 `div`，缺少键盘触发；更多菜单缺少 `aria-label`。
- 部分工作区轨道按钮及图标控制缺少稳定的可访问名称。

影响：键盘用户无法可靠完成核心路径，且视觉上无法确认当前焦点。

### P1 — 任务主界面存在隐藏导航

Tasks Board、Session Hub、Usage 被做成 300% 宽横向页面，切换箭头默认隐藏并依赖 hover。用户无法从静态界面理解还有两个工作区，也不容易形成稳定的空间模型。

影响：核心能力的发现率低，第一次使用时容易误判产品只有看板。

### P1 — 关键任务错误缺少可恢复反馈

任务状态更新失败会静默回滚，删除失败只进入控制台；项目任务错误态也没有明确重试或修复动作。

影响：用户看到状态“跳回去”却不知道原因，破坏本地工程工具最重要的可检查性与信任感。

## P2 问题

- Settings 有 16 个平级入口，缺少分组、搜索、当前页标题和渐进披露。
- Settings 浅色侧栏的装饰渐变、强 blur 与大阴影偏离“玻璃服务结构、状态色传达含义、静止态扁平”的项目规范。
- Project Detail 仍是通用卡片仪表盘，和项目→任务→Worktree→会话的工程模型衔接不强。
- Composer 同时暴露过多控制，首次发送前的决策成本高。
- 11px 文本至少在 6 处出现，低于项目紧凑字号下限 12px。
- 中英文与省略号等微文案仍不一致，错误态缺少下一步动作。

## Codeg 值得借鉴的部分

- 持续可见的 New Chat、Search、Automations、Tasks 与文件夹/会话树，降低回忆成本。
- 从工作区首页直接进入输入，先让用户完成第一轮，再暴露复杂 Agent 配置。
- Agent 不可用时提供原地修复入口，并保留用户草稿与上下文。
- Split View、会话树和最近会话对高频切换更友好。

不建议照搬 Codeg 的大号渐变标题、技能彩色卡片、胶囊泛用、能力陈列式首页或将 Coding/Office/Research 等权重并列。它们会稀释 VibeX 的专业工程交付定位。

## 建议路线图

### Now

1. 修复核心交互的焦点、键盘语义、可访问名称和可恢复错误态。
2. 将 New Session、Search、Needs Me、Automations 做成带文字标签的稳定动作层。
3. 把首次价值路径压缩为：选择项目/文件夹 → 输入任务 → 安全默认发送；将分支、模式、历史等折叠为高级设置。
4. 统一危险权限契约：默认安全，Full Access 明确解释后果、显式确认，并在发送附近持续显示状态。

### Next

1. 用已有自动化模板生成 3–4 个与当前 Git/CI 状态相关的上下文快捷任务，只预填、不自动运行。
2. 重构 Settings 信息架构为“快速设置 / 工作流 / 访问与运维 / 高级原生配置”。
3. 强化最近会话、导入历史、跨 Agent 搜索和 Needs Me 跨项目队列。
4. 重做 Project Detail，让它成为项目行动与交付证据的入口，而不是卡片集合。

### Later

- 远程伴侣与移动端只作为查看、审批、Needs Me 和恢复会话的补充。
- 把可信工作流打包为可复用模板，形成从隔离执行到检查、Review、Git 交付的闭环。

## 产品定位建议

> VibeX：在一个本地工程驾驶舱里，安全地运行、检查并交付多个 AI coding agent 的并行工作。

北极星指标：每周完成“Agent 执行 → 用户检查证据 → Git/Review/Follow-up”的活跃项目数。

护栏指标：危险权限开启率、不可逆操作失败率、Preflight 修复成功率、待审批中位时长。

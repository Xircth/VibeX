# Product

## Register

product

## Category & Positioning

**VibeX** is an **All-in-One Agent-Native Development Platform** uniting a visual multi-agent development environment and a Vibe Coding toolkit on a high-performance, highly decoupled Rust core where **everything is a plugin**.

Developers use VibeX to visualize and orchestrate **20+ Coding Agents** (Claude Code, Codex, OpenCode, Cursor, Antigravity, DeepSeek, Grok, Cline, Kimi Code, CodeBuddy, Qoder, TRAE CLI, and the open ACP ecosystem) across free split-tab and Infinite Canvas workspaces, isolated Git worktrees, 3-tier agent collaboration flows, cross-agent session handoffs, and connected Mobile / Desktop / WebUI / Server hosts.

## Users

VibeX serves software engineers, tech leads, and AI-native Vibe Coders who run multiple coding agents concurrently against real codebases.

The primary user is technical, keyboard-fluent, and outcome-driven. In a typical session they advance several parallel workstreams at once: framing context with `@` references and live browser element picking, delegating subtasks via `&Agent` or multi-Bot collaboration rooms, migrating or steering sessions across agents without losing context, reviewing diffs or 3-pane merges across isolated Git worktrees, and continuing runs seamlessly from desktop, WebUI, remote servers, native iOS/Android apps, or IM channels.

## Product Purpose

Success means a developer gets the best possible Vibe Coding experience—directing a coordinated team of heterogeneous coding agents at high concurrency without losing code hygiene, session continuity, auth/quota clarity, or human control:

1. **Visualize and unify heterogeneous agents** — run 20+ coding agents in one transparent environment (**dedicated native Agent engine adapters first, ACP compatibility second**) with unified management of official subscriptions, API keys, provider presets, model routing, and live usage/quota visibility.
2. **Fluid dual workspaces** — switch losslessly between **Free Split Tabs** for deep focus and an **Infinite Spatial Canvas** where dozens of live agent windows, editors, diffs, terminals, and browsers work side by side.
3. **Collaborate and migrate freely across agents** — combine `&Agent` delegation, persistent AI team collaboration rooms, and visual workflows with seamless **cross-agent session migration**, in-flight **Live Steering**, and non-destructive **Session Forking**.
4. **Multi-Worktree engineering & Multi-Host connectivity** — isolate parallel agent work in Git worktrees with built-in diff/merge review, while keeping Desktop, WebUI, headless Server, SSH, encrypted peer links, native Mobile apps, and chat bots connected in real time.
5. **Everything is a Plugin** — keep the core fast and lightweight while delivering Vibe Coding tools (Browser, Office, Computer Use, Code Completion, Voice Input, Research Skills, and community extensions) as modular, on-demand plugins.

## Brand Personality

Calm, inspectable, and precise.

VibeX feels like a high-craft engineering cockpit (aligned with macOS Tahoe Liquid-Glass chrome over opaque, high-contrast content surfaces documented in `DESIGN.md`). Polish serves scanability, state honesty, and low cognitive friction across multi-hour sessions. Copy is direct, concrete, and free of hype.

## Anti-references

- Legacy task-ticket Kanban trackers where rigid 4-column CRUD boards replace live agent workspaces and code context.
- Generic AI SaaS dashboards with oversized promotional cards, decorative gradients, neon glow, or vague productivity slogans.
- Raw terminal multiplexers copied into a GUI without hierarchy, progressive disclosure, structured diffs, or permission clarity.
- Fabricated telemetry or silent fallbacks — missing usage, quota, or capability states remain explicitly absent rather than padded with zeroes or guessed from free text.
- Fragmented component vocabularies where workspace panels, canvas nodes, collaboration rooms, settings, and plugins feel like separate apps.

## Design Principles

1. **Make live state legible at a glance.** Turn lifecycle (`in-flight`, `blocked`, `completed`, `failed`, `cancelled`, `interrupted`), worktree branch ownership, agent readiness, and pending approvals must be unmistakable before any decorative treatment.
2. **Dense, never noisy.** Support high information density—multi-pane splits, 24-window spatial canvases, streaming tool calls, and diff hunks—through disciplined typography, spacing tokens, and progressive disclosure.
3. **One product vocabulary across every surface.** Buttons, inputs, chips, tabs, context menus, dialogs, and status indicators share radius, border, focus, and token semantics (`DESIGN.md`) across built-in views and plugins alike.
4. **Treat color strictly as signal.** Semantic accents communicate selection, focus, session slot linkage, diff polarity, and turn health—never background ornament.
5. **Preserve human authority at every boundary.** Destructive git operations, tool permissions, workflow completion gates, interrupted turns, and Full-Trust plugin installations require explicit, inspectable user intent.

## Accessibility & Inclusion

Target WCAG AA contrast across light and night-scene palettes (`DESIGN.md`). Never rely on color alone to convey turn, git, approval, or connection status. Maintain full keyboard navigation, focus rings, command-palette reachability, and `prefers-reduced-motion` fallbacks across both Dockview IDE panes and the Infinite Spatial Canvas.

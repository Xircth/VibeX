# Agent 安装与认证是独立生命周期

Agent 的安装完成不以用户已经登录为前提：本地 runtime 与 ACP 组件安装、版本和
路径校验以及 ACP `initialize` 握手通过后，该 Agent 即为已安装。需要认证但探测为
暂未登录或未配置凭据的 Agent 进入待认证状态，继续显示在 Agent 设置中；账号登录
由用户在官方 Agent 中完成，只有满足认证与必要配置条件的就绪 Agent 才能用于创建
新会话。

认证失败或用户暂缓认证不会回滚、删除已经验证通过的安装。安装状态、认证状态与
会话可用性必须分别表达，不能再用单一的“已配置”或“已启用”布尔值混合表示。

“添加并安装”只自动执行无需用户交互的下载、校验、安装与 ACP 握手。账号登录、
浏览器授权、设备码和 CLI 登录不属于 VibeX 流程；需要时用户在官方 Agent 中完成。
Built-in Agent Profile 已适配的原生 Runtime 配置字段可由用户在详情页明确编辑；
其中包括 API URL、API Key、模型、推理强度与 Runtime 自身支持的常用选项。VibeX
不得自动写入默认凭据，也不得把 ACP 会话选项误写成持久配置。

“立即检查”始终是只读探测；只有用户明确选择“修复”才执行下载、校验、安装等写操作。
进入设置页、应用启动及其他后台探测都不得自动修复。

Runtime 完整性、必需组件或 ACP 握手失败时，Agent 需要修复且不能创建会话；必需
认证能力无法确认时，Agent 仍为已安装但不能就绪。订阅可见性、账户详情等可选管理
能力探测失败时，Agent 保持就绪，仅对应能力进入降级状态并提供诊断与重试。“未提供
该能力”与“已提供但探测失败”必须分别表达。

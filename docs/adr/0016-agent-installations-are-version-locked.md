# Agent 安装精确锁定版本并由用户确认升级

每次安装都把计划中的确切包版本写入用户环境（`pkg@1.2.3`），并在 Installation
lock 中记录当时观察到的路径、版本与来源。安装目标优先解析 npm `dist-tags.latest`
（Runtime 与 ACP 各自解析）；网络不可用时回退 Built-in Profile 钉。启动时不把
`latest` 交给会话进程，但会优先使用 PATH 上同名命令，再回退 lock 里的绝对路径。
普通 Registry Agent 首次安装时锁定用户确认时 Registry 提供的具体版本。用户可以
指定 Runtime / ACP 版本；不兼容只提示风险，不阻止安装。安装落点是用户环境。

检查更新时自动刷新 Registry；过期快照不再阻止安装。用户确认更新后，按同一
用户环境命令安装新版本；失败时继续使用旧 lock。用户在终端自行升级后，VibeX
发现版本变化只重新校验并重绑，不把内容指纹变化当成安装损坏。

“有可用更新”不是故障状态：导航带继续显示当前安装的健康与就绪徽标，详情页预
检查列表显示版本差异与手动更新入口。只有当前安装本身失效时才进入需要修复状态。

更新尝试被取消、失败或因应用退出而中断时同样不改变当前 Installation lock；
已经验证的旧版本继续可用，未完成的新版本只作为暂存产物被协调或清理。所有中断
的安装尝试都等待用户明确重试，不在启动恢复期间自动续跑。

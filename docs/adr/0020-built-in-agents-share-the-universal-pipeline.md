# 内置 Agent 与普通 Agent 使用同一管线

所有 Agent 使用同一套设置页面、状态模型、预检查、安装、认证、配置、更新、卸载
和会话运行管线，不为 Codex、Claude Code、OpenCode 或 Pi 编写专属配置面板、
安装流程或会话逻辑。Agent 来源只提供归一化的声明数据：普通 Agent 来自官方
Registry，内置 Agent 来自 VibeX 预置的 Built-in Agent Profile。

统一详情页以状态驱动的分组呈现：顶部摘要与启用控制、预检查、运行环境与安装、认证
与账户、配置、诊断与高级操作。非就绪或正在操作时自动展开预检查，就绪时将其折叠为
摘要；某项可选能力未被广告时不显示且不视为失败。内置身份不得改变这一页面骨架。
失败通过 Toast 即时提示，不在详情顶部堆叠错误；预检查区保留失败状态与修复或重试
操作，诊断区提供完整可复制的命令输出、校验值和探测事件。
用户主动操作成功的 Toast 自动收起；失败 Toast 保留至用户关闭，并提供“查看”操作
以定位对应 Agent 的预检查失败项。
诊断区每个 Agent 仅保留最近 20 次安装、更新、修复与探测记录，用户可单独清除；
即使 API Key 可在本机明文保存，诊断记录中的 API Key 与令牌也必须脱敏。

Built-in Agent Profile 可以声明 Registry 未表达的本地 Runtime、ACP 适配器、
检测候选和验证版本组合，也可以引用统一扩展接口中的管理能力 Provider，但不能
产生专属设置页面、状态机、安装流程或会话逻辑。
“内置”只决定默认加入导航带、Registry 置顶、不可移除以及主动检查现有本地安装；
历史导入、API Key、模型配置等能力必须由统一机制或 ACP 能力提供，不能由内置身份
自动获得。

本决策取代 ADR-0008 与 ADR-0009 中将内置 Agent 定义为增强能力支持层和专属安装
契约的部分。

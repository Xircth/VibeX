# VibeX 0.1.5

## 中文

VibeX 0.1.5 把内置 Gemini CLI 换成 Google Antigravity，重做首次启动，并补齐 Host 隧道、会话工作台、插件开发和聊天通道。

### 主要更新

- 内置 Agent 中的 Gemini CLI 退役，由 Google Antigravity 接手同一安装、认证和会话管线。已有成员、设置和安装记录会迁到新身份；历史会话里的 `gemini` 拼写仍可读取。
- 首次启动改为产品主视觉、使用声明，以及 Git / GitHub CLI 安装。本机还没有 Git 身份时，可以在向导里写好姓名和邮箱再继续。
- Host 可以保存和启用 FRP 隧道，配对邀请带上当前可达地址。系统代理区分模式，局域网发布失败时不会把无效 origin 留在名单里。
- 会话列表按工作台状态分组：进行中、待审阅、已完成。看过最新回合之后，条目才会从待审阅里离开。
- 子会话可以在时间线里直接打开。Agent 声明的斜杠命令和 Skill 进入 Composer，不再把「还没收到目录」显示成空列表。
- 链接开发中的插件会跟随源目录刷新；`npx vibex plugin` 覆盖打包、测试和控制面操作。多智能体协同插件里的 mention 身份同步为 Antigravity。
- 聊天通道的入站命令和出站通知都走当前 Host。授权发送者可以远程建任务、审批、取消回合，空白名单时入站保持关闭。
- Agent 设置显示当前账户，鉴权模式用标签页区分。应用图标按当前品牌重新生成。

## English

VibeX 0.1.5 replaces the built-in Gemini CLI with Google Antigravity, rebuilds first-run setup, and fills in Host tunnels, the session workbench, plugin development, and chat-channel control.

### Highlights

- Google Antigravity takes over the built-in Gemini CLI slot on the same install, auth, and conversation pipeline. Existing membership and settings move to the new identity; historical `gemini` spellings still read.
- First-run now opens with the product hero, an explicit usage disclaimer, and Git / GitHub CLI setup. If this machine has no Git identity yet, the wizard collects a name and email before continuing.
- Hosts can save and enable FRP tunnels, and pairing invitations include the current reachable addresses. System proxy settings distinguish modes, and failed LAN publishes do not linger as origins.
- The session list groups by workbench state: in progress, needs review, and done. A session leaves review only after its latest turn has been viewed.
- Child conversations open from the timeline. Agent-advertised slash commands and skills appear in the composer; a missing catalog stays missing instead of rendering as empty.
- Linked development plugins refresh when their source directory changes. `npx vibex plugin` covers package, test, and control-plane operations. Multi-agent mention URIs now target Antigravity.
- Chat-channel inbound commands and outbound notices belong to the current Host. Authorized senders can create tasks, approve, and cancel remotely; inbound stays closed when the allow-list is empty.
- Agent settings show the signed-in account, auth modes use tabs, and the app icon set is regenerated from the current mark.

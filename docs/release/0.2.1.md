# VibeX 0.2.1

## 中文

VibeX 0.2.1 把插件做成完整产品面：Host 窗口可以接到已保存的远端 Host，官方 Remote SSH 能在 SSH 机器上装起 Server，Composer 可以引用这些 Host。同时补上会话分叉、在途纠偏、插件市场搜索，以及看板、文件树、GitHub CLI 和 Windows 输入上的一批缺口。

### 一、修复

1. 绑定远端 Host 的窗口里，应用外壳、终端和启动预检继续走当前 Host，不再掉回本机后端。
2. 已保存的 SSH Host 再次连接时，会先启用对应供给插件并重建隧道，而不是拿着过期地址硬连。
3. 没有启用供给插件时，会提示先启用，而不是连接失败后才发现原因。
4. 欢迎页拖入文件夹会走「选择文件夹」同一条打开路径，不再被当成无效放置。
5. Windows 上 Enter 发送消息，拖入的文件会作为附件，不再被忽略。
6. 隐藏编辑器和终端时，文件树仍留在原位。
7. 尚未加载完的文件夹里也可以新建文件或文件夹，不再被空子节点挡住。
8. Agent 安装 / 更新进度能识别嵌套或驼峰字段的事件，失败时给出操作结果，而不再卡住或漏提示。
9. 已配置的供应商凭据算作预检通过，不再被误判成未就绪。
10. Agent 启动只把门禁放在 ACP 适配器上，并与 PATH 上的运行时探测共用同一套发现。
11. 不在 npm 包内的厂商 CLI 指纹会被正确采用，不再误报运行时不匹配。
12. 看板画布的拖放提示和分组缩放恢复类型检查，避免提示错位或缩放失效。
13. 已安装插件列表恢复圆角。
14. 模块联邦运行时可以解析，插件 Host+App 表面不再空白。
15. 创作样例不再出现在插件市场和发行物里。
16. GitHub 登录改为在 Host 终端里完成；未安装 `gh` 时可以由 Host 装进用户环境。
17. 用量看板的 token 类型与缓存环显示不再挤在一起。
18. 新建会话默认落到上次使用的工作区；工具栏和右侧栏的会话导航留在当前对话。
19. Agent 终端和用户 PTY 使用设置里的默认 shell；Warp 当作外部应用打开；进程重启后重新挂上输出。

### 二、优化

1. 会话时间线改为快照加行窗口打开，长对话进入更快。
2. Agent 管理事件有界，终端输出满时丢掉最旧一段，避免内存持续上涨。
3. 会话看板与无限画布是同一偏好的两种视图，切换箭头不再在两者之间空转。
4. 会话监控列只在确有监控对象时出现，空列不再占位。
5. 插件市场可以按名称、简介、作者和版本搜索官方与社区条目。
6. 跟进输入会记住本会话历史，↑ / ↓ 可翻出上一条。
7. 插件作者可以拿到运行时证据和 Host chrome 脚手架，开发包文档补上 Remote SSH。

### 三、新增

1. 官方 Remote SSH 插件：在能 SSH 登录的机器上安装并启动 `vibex-server`，经本机隧道写入「远程连接」，并打开新窗口接入该 Host。
2. 桌面可以绑定应用窗口到已保存 Host，用地址和令牌连接；Host 会公布可达地址，并支持远端升级。
3. 欢迎页增加「新建窗口」，本机再开一个未绑定远端的应用窗口。
4. Composer `@` 增加 Host 引用：把已保存 SSH Host（以及本机）写成连接文件，供 Agent 使用。
5. 可以从一条已完成的 Assistant 消息分出新会话；在 Agent 支持时保持 ACP 上下文连续。
6. Agent 声明支持纠偏时，Composer 可以把指导送到当前在途回合，而不另开新回合。
7. 插件可以贡献 Host chrome、模型供应商导入源，并在确认后写入供应商预设。
8. 设置 → 版本控制可以安装 GitHub CLI，并在 Host 终端里完成 `gh auth login`。
9. 模型供应商预设回到 Host 存储：可以恢复旧预设、一次选择多个模型，并投影到 Codex / Pi / OpenClaw。

## English

VibeX 0.2.1 turns plugins into a product surface: App windows can bind to a saved remote Host, official Remote SSH can install Server over SSH, and Composer can reference those Hosts. It also adds conversation fork, in-flight steering, marketplace search, and closes gaps in the session board, file tree, GitHub CLI, and Windows input.

### Fixes

1. An App window bound to a remote Host keeps chrome, terminals, and preflight on that Host instead of falling back to the local backend.
2. Reconnecting a saved SSH Host enables the provisioner and rebuilds the tunnel instead of using a stale origin.
3. If the provisioner plugin is off, the UI asks you to enable it instead of failing the connect with no cause.
4. Dropping a folder on Welcome follows the same path as Select Folder.
5. On Windows, Enter sends the message and dropped files attach instead of being ignored.
6. Hiding the editor and terminal leaves the file tree in place.
7. You can create a file or folder inside a lazy directory that has not finished loading.
8. Agent install / update progress reads nested or camelCase events and reports failure instead of stalling.
9. Configured provider credentials count as preflight-ready.
10. Agent launch gates on the ACP adapter and shares PATH runtime discovery.
11. Vendor CLI fingerprints outside npm packages are accepted instead of reporting a runtime mismatch.
12. Kanban canvas drop hints and group resize keep their type checks, so hints and resize stay aligned.
13. The installed plugin list keeps its rounded corners.
14. The module federation runtime resolves, so Host+App plugin surfaces are not blank.
15. Authoring samples stay out of the marketplace and the release.
16. GitHub login happens in a Host terminal. If `gh` is missing, the Host can install it into the user environment.
17. The usage dashboard token type and cache ring no longer collide.
18. New session defaults to the last-used workspace. Toolbar and right-panel session navigation stay on the current conversation.
19. Agent terminals and user PTYs use the configured default shell. Warp opens as an external app. Output reattaches after a process restart.

### Improvements

1. Conversation timelines open from a snapshot plus a row window, so long threads load faster.
2. Agent manager events are bounded. Terminal output drops the oldest chunk when full.
3. Sessions and infinite canvas are two views of one preference. Arrow switching does not rotate through both.
4. The session monitor column appears only when something is monitored.
5. The plugin marketplace searches official and community listings by name, summary, author, and version.
6. Follow-up input remembers this session's history. Up / Down recalls the previous line.
7. Plugin authors get runtime evidence and Host chrome scaffolds. The development pack documents Remote SSH.

### Features

1. Official Remote SSH plugin: install and start `vibex-server` on an SSH host, write it into Remote connections through a local tunnel, and open a new window bound to that Host.
2. Desktop App windows can bind to a saved Host with origin and token. The Host advertises reachable addresses and can apply a remote upgrade.
3. Welcome adds New Window, which opens another local App window that is not bound to a remote Host.
4. Composer `@` adds a Host tab: saved SSH Hosts (and this computer) become connection files the Agent can use.
5. Fork a new conversation from a completed Assistant message. ACP context stays continuous when the Agent supports it.
6. When the Agent advertises steering, Composer sends guidance to the in-flight turn instead of starting a new one.
7. Plugins can contribute Host chrome and model-provider import sources, and write provider presets after confirmation.
8. Settings → Version Control can install GitHub CLI and run `gh auth login` in a Host terminal.
9. Model Provider presets live on the Host again: restore legacy presets, select multiple models, and project them onto Codex / Pi / OpenClaw.

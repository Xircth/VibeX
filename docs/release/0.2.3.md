# VibeX 0.2.3

## 中文

VibeX 0.2.3 把 Pi 的项目文件改成必须由你明确信任，新建 worktree 会话可以带上未提交更改，插件也可以直接从归档安装。会话失败原因说清楚，Pi 的生命周期提示不再混进助手回复。

### 一、修复

1. Pi 不再在启动时自动信任工作区。仓库里的 `.pi` 文件（含启动即执行的扩展）必须先经过你确认，才会被加载。
2. 创建工作区时，分支已在其他工作树中检出、仓库正在合并 / 变基 / cherry-pick / revert、或 sparse-checkout 得到空目录，都会给出可处理的错误，不再当成内部失败。
3. Pi 的启动横幅、重试和上下文压缩提示记成会话通知，不再写进助手回复。
4. 内置 Agent 按所选鉴权模式启动时，会清掉冲突的环境凭据，避免订阅模式带上旧的 API Key 或自定义端点。
5. npm CLI 发布包名为 `@omnione/vibex`（`npx @omnione/vibex`）。0.2.2 发行物里的 `vibexs` 包名不再使用。
6. 插件 Worker 按 Full Trust 执行；安装即信任，不再用 capability grant 当第二道授权门。

### 二、优化

1. 文件树按需加载目录。大仓库达到上限时明确截断；`node_modules`、`target` 这类依赖和构建目录不再当普通树展开。
2. Pi 设置可以给模型配置推理强度，并查看、撤销 `trust.json` 中的项目信任条目。
3. 新建会话失败时只显示可处理的原因，不再把内部错误细节铺在表单上。
4. 文件树列举由 Host 统一提供，桌面和 Server 行为一致。
5. Pi 启动会绑定本机 `pi` 可执行文件和已保存的 Provider Key，不再依赖隐式 PATH 猜测。

### 三、新增

1. Pi 项目信任：打开 Pi 会话时，可以信任、拒绝或撤销加载该工作区的项目文件。未确认的已有授权也会再次提示。
2. 新建 worktree 会话时可以选择「复制未提交更改」，把当前工作区的未提交内容带到新工作树，不改动原工作区。
3. 插件可以从 zip 或 tar.gz 归档安装；归档大小、条目数和解压总量有上限，路径越界会被拒绝。

## English

VibeX 0.2.3 makes Pi project files an explicit trust decision, lets a new worktree session carry uncommitted changes, and installs plugins from archives. Session failures are actionable. Pi lifecycle notices no longer land in the assistant transcript.

### Fixes

1. Pi no longer auto-trusts a workspace on launch. Repo `.pi` files, including extensions that run at startup, load only after you confirm.
2. Creating a workspace now reports when a branch is already checked out, when merge / rebase / cherry-pick / revert is in progress, or when sparse-checkout produced an empty tree, instead of an internal error.
3. Pi startup banners, retries, and context-compaction notices are session notices, not assistant messages.
4. Built-in Agents scrub conflicting launch credentials for the selected auth mode, so a subscription launch does not inherit an old API key or custom endpoint.
5. The npm CLI package is `@omnione/vibex` (`npx @omnione/vibex`). The `vibexs` name from the 0.2.2 asset is no longer used.
6. Plugin Workers run as Full Trust. Installing the package is the trust decision; capability grants are not a second authorization gate.

### Improvements

1. The file tree loads directories on demand. Large trees truncate at a cap. Dependency and build directories such as `node_modules` and `target` are not expanded as ordinary folders.
2. Pi settings can configure model thinking levels and review or revoke `trust.json` entries.
3. Session creation shows an actionable reason instead of dumping internal error text onto the form.
4. Directory listing is served by the Host, so desktop and Server behave the same.
5. Pi launch binds the local `pi` executable and the saved Provider key instead of guessing from PATH.

### Features

1. Pi project trust: a Pi session can trust, decline, or revoke loading that workspace's project files. An in-force grant that was never acknowledged is prompted again.
2. A new worktree session can copy uncommitted changes from the current workspace without modifying it.
3. Plugins can be installed from zip or tar.gz archives. Archive size, entry count, extracted size, and path traversal are bounded.

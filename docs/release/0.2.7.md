# VibeX 0.2.7

## 中文

VibeX 0.2.7 把 ACP 会话建立提前到打开对话时完成，发送只走 `session/prompt`。打开历史会话即可续上原来的 Agent 线程，发送按钮在绑定完成前保持关闭。Windows 内置浏览器改到独立弹出层上，避免和 WebView2 叠在一起后页面冻住或 GPU 崩溃。

这是 0.2.7 的正式重建。此前因打开会话后一直显示「正在连接」、空闲时报 `connection not found`、对话能聊却不可用，该版本曾被撤回。本次把绑定状态、发送闸和自动重连收成同一条路径后再发布。

### 一、修复

1. 打开对话即完成 ACP 绑定（`session/new` / `resume` → `load` → `new`）。Prompt 不再调用 `session/new`，避免 Codex 被分到另一条线程。
2. 绑定成功发出 `SessionBindReady`。前端以该事件解锁发送，不再只依赖一次可能被取消的 `ensureSessionControls`。
3. resume 把连接标成 Recovering 后，绑定成功会改回 Ready。活着的 Connecting / Recovering 连接不再被当成失踪。
4. 空闲会话不再弹出「操作失败：agent connection was not found」。自动重连也不会拆掉正在建立的连接。
5. 发消息使用会话当前连接，不用过期的 connection id。
6. 无在途回合的 bind/status 事件撞上外键时跳过，不再中断事件记录。
7. Windows 主窗口补上 `allow-show`，首次绘制即可显示，不再等 8 秒兜底。
8. Windows 任务栏跳转列表使用开发版真实 AppID，并为任务补上标题。
9. 开发启动会按路径结束占用 `vibex.exe` 的旧进程，避免无法覆盖二进制。
10. Pi 未安装视为配置状态，不再当内部运行时崩溃刷屏。
11. Windows 上 CEF 页面不再作为 WebView2 的子窗口。页面在 Tauri 窗口拥有的弹出层上绘制，GPU 崩溃（`0x80000003`）和睡眠后不再把界面冻住。
12. Chromium 消息泵不再从 `CefDoMessageLoopWork` 里重入。delay=0 的工作先离开 UI 线程再投递，嵌套泵不会丢掉绘制。
13. 额外的本地应用窗口共用主窗口的 WebView2 配置目录。从 IPC 再开一套独立环境会让新窗口空白、关不掉，调用方也会卡住。
14. ACP 子进程或 stdio 在回合中途断开时，当前回合记为 `connection_closed`，并清掉卡住的 active turn。没有输出的静默回合会重拉连接。
15. Composer 替换正文走系统撤销栈，不再把 React 赋值绕过撤销。
16. 看板画布自己接管右键拖移。不再依赖 React Flow 的 `panOnDrag`，Chromium 才能持续收到 mousemove。
17. 文件树截断列表回来后，仍然有效的展开目录不会被清掉。

### 二、优化

1. 标题栏 Logo 收成独立菜单：新建应用窗口、回到首页、最近项目。
2. `title` 不再弹出系统原生提示。悬停由应用内提示层显示，位置避开视口边缘。
3. Pi 推理字段从 Pi 面板抽到统一的模型供应商表单。新声明的推理档位默认不含 `xhigh`。
4. Agent 鉴权 Tab 按 Agent 记住。从已绑定的模型供应商切到官方订阅会立即保存，不会被下一轮加载弹回。
5. 桌面打开设置可以带到指定路径。
6. 会话中枢侧栏搜索同时匹配会话名和对话内容；空看板仍显示四个状态分组。
7. 应用图标重新生成。

### 三、新增

1. 打开标签即 connect：Conversation 行存在后立刻建立 ACP 会话，Desktop、Server、Automation 共用同一条 `conversation_ensure_session_controls`。
2. Windows CEF 拥有弹出层宿主（`VibeXBrowserHost`），与 WebView2 分层绘制。
3. 原生 `title` 的应用内悬停提示。

## English

VibeX 0.2.7 binds the ACP session when you open a conversation. Sending is only `session/prompt`. Reopening history resumes the original Agent thread, and the send button stays off until bind finishes. On Windows the embedded browser lives in an owned popup so it no longer freezes or crashes the GPU under WebView2.

This is a rebuild of 0.2.7. The first cut was pulled because opening a session left "Connecting to agent…" up, idle sessions toasted `connection not found`, and a usable transcript still could not send. Bind state, the send gate, and auto-reconnect now share one path.

### Fixes

1. Opening a conversation completes ACP bind (`session/new` / `resume` → `load` → `new`). Prompt no longer calls `session/new`, which forked Codex onto another thread.
2. Bind success emits `SessionBindReady`. The frontend unlocks send on that event instead of a single `ensureSessionControls` promise that could be cancelled.
3. After resume marks a connection Recovering, bind success restores Ready. Live Connecting / Recovering connections are not treated as missing.
4. An idle conversation no longer toasts "Action failed: agent connection was not found". Auto-reconnect does not tear down a bind still in flight.
5. Sending uses the conversation's current connection, not a stale connection id.
6. Bind and status events with no in-flight turn skip a foreign-key miss instead of aborting the recorder.
7. The Windows main window has `allow-show`, so the first paint can reveal it without the 8-second fallback.
8. The Windows jump list uses the real dev AppID and sets a title on each task.
9. Dev startup terminates a stale `vibex.exe` by path so the debug binary can be replaced.
10. A missing Pi install is a configuration state, not an internal runtime crash.
11. On Windows, CEF pages are no longer a child of WebView2. They paint in a popup owned by the Tauri window, so GPU crashes (`0x80000003`) and sleep no longer freeze the UI.
12. The Chromium message pump no longer re-enters from `CefDoMessageLoopWork`. delay=0 work hops off the UI thread before it is posted, so a nested pump cannot drop paints.
13. Extra local app windows share the main WebView2 profile. Creating a second environment from IPC leaves the new window blank and unclosable, and freezes the caller.
14. If the ACP child or stdio dies mid-turn, that turn is `connection_closed` and the stuck active turn is cleared. A silent turn with no output reconnects.
15. Composer replacements go through the native undo stack instead of assigning React state around it.
16. The session canvas owns right-drag pan. It no longer relies on React Flow `panOnDrag`, so Chromium keeps sending mousemove.
17. A truncated file-tree listing no longer clears expanded folders that are still valid.

### Improvements

1. The title-bar logo is its own menu: new app window, back home, recent projects.
2. Native `title` tips are suppressed. Hover uses an in-app tooltip that stays inside the viewport.
3. Pi reasoning fields move from the Pi panel onto the shared model-provider form. Newly declared reasoning omits `xhigh` by default.
4. The Agent auth tab is remembered per agent. Switching to official subscription from a bound model provider persists immediately and does not snap back on reload.
5. Opening Settings on desktop can land on a specific path.
6. Session hub search matches conversation content as well as names. An empty board still shows the four status groups.
7. App icons are regenerated.

### Features

1. Open-tab connect: after the Conversation row exists, the host binds an ACP session immediately. Desktop, Server, and Automation share `conversation_ensure_session_controls`.
2. Windows CEF owned-popup host (`VibeXBrowserHost`), composited above WebView2.
3. In-app hover tooltips for native `title` attributes.

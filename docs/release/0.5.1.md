# Dimo 0.5.1

## 中文

Dimo 0.5.1 重新发布。这个构建修复更新时删掉会话数据的问题，并保留本版原有的工作流、画布和时间线改动。

0.5.0 和最初的 0.5.1 把唯一的会话数据库放在安装目录里。macOS 应用内更新会整包替换 `Dimo.app`，安装目录里的数据库会在新版本启动之前被删掉。本构建把正式版数据目录移到安装包外面，启动时收回旧目录里的数据库，并在替换安装包之前再迁一次。

### 重要修复

1. **更新不再删除会话数据**
   - 正式版数据库改到系统用户目录，不再放在安装目录：
     - Windows：`%APPDATA%\dimo\dimo\data`
     - macOS：`~/Library/Application Support/app.dimo.dimo`
     - Linux：`~/.local/share/dimo`
   - 第一次启动会把安装目录、旧版 VibeX 目录，以及旁边带 `db.sqlite` 的 `*.superseded-*` 副本收进这个目录。有会话的库优先保留，另一份只改名留存，不删除。
   - 应用内更新在替换安装包之前会再迁一次。macOS 上如果数据库仍在 `.app` 里面，更新会中止，并提示先完全退出、重新打开确认会话还在，然后再更新。
   - 已经完成的 macOS 0.5.0 / 0.5.1 更新救不回当时被删掉的那一份。Windows 上如果 `%LOCALAPPDATA%\Dimo\data\db.sqlite` 还在，第一次打开本构建会被收进上面的目录。
   - 数据仍在 `Dimo.app/Contents/MacOS/data` 里时，请先打开本构建一次，或先把该目录拷出来，再替换 `Dimo.app`。

### 一、新增

1. **Workflow Studio：完整测试、发布与未命名任务保护**
   - 工具栏新增完整测试、发布任务，以及画布上一步 / 下一步。节点检查器可以读取当前会话配置。
   - 离开未命名草稿（「新建任务」/「New Task」）前必须先命名，避免下一次打开覆盖 `~/.dimo/workflows/新建任务.dimo-workflow.json` 并丢掉已有编排。
   - 工作流工具会标出当前画布正在查看的定义（`canvasViewing` 与 `dimo.canvas.viewing`）。共享工作流目录里只保留一份未命名草稿。

2. **多提供商模型分组菜单**
   - OpenCode、DSH、OMP 等以 `provider/model` 列出的模型，按提供商收成一行，悬停子菜单只显示该提供商的模型。选中值仍是完整 id。
   - Claude、Codex、Grok 等没有此前缀的目录保持平铺。会话设置、新建会话和智能体默认值共用这一分组。

### 二、优化

1. **对话时间线与用户消息排版**
   - 可见虚拟行放进同一个随滚动平移的窗口里堆叠。高度估算偏短时，后一轮不再盖住前一轮。
   - 助手虚拟行改用内容稳定的键：工具调用用 `tool_use_id`，正文和思考用内容摘要。前面插入工具调用时，已经量过的高度会留下来。
   - 还没登记排序的回合排在全局侧栏行之后，不再挤进同一条排序带。
   - 用户消息里的中文序号（`1.`、`1、`、`1）`）和粘在一行里的有序列表，会整理成 Markdown 能识别的列表。

2. **无限画布、自由标签与壳层导航**
   - 从画布切回自由标签时，最多打开 10 个最近活动的节点，避免一次铺开整张画布。
   - 会话列表色标与画布节点头使用同一套槽位顺序。
   - 左侧 / 右侧壳层导航可以互换位置。拖动手柄、只在一侧有面板时打开新面板，不再把面板藏进错误分组；空分组会延后关闭。

3. **启动主题与移动设备提醒**
   - 启动时按已保存的浅色或深色主题铺窗口底色。浅色主题不再继承系统的深色 WebView 背景。
   - 设置窗口和桌面 toast 不再把主窗口拉到前台。
   - 已配对手机的离线提醒按设备静默 24 小时。正在进行的连接请求，以及刚连上的短确认，不受这个限制。

4. **ACP 每次启动使用独立临时目录**
   - ACP 会话和 Antigravity 登录各自使用 `run-<id>` 临时目录，进程结束后连同 PyInstaller `_MEI*` 解压树一起删除。
   - 应用启动时清扫已解锁的残留目录，跳过仍被占用的目录、活着的进程，以及两分钟内的新目录。原生 Claude / Codex 仍使用稳定临时目录。

### 三、修复

1. **Antigravity 官方登录与 ACP 会话泵**
   - 官方登录会打开 `authenticate` 返回的授权链接，而不再只把 `session/new` 挂起。
   - 超长或缺少换行的 ACP 标准输出帧会被丢弃，读缓冲随之收缩，避免单条巨型 JSON-RPC 帧一直占着内存。
   - 事件通道在落盘变慢时不再堵住所有并发会话，使它们停在「生成中」。高量增量可以丢弃，结束事件仍然进得去。只取消当前这一条提示时，会发出已取消的结束事件。

2. **DSH 提供商删除与更名前的插件清单**
   - 删除 DSH 提供商时，只清掉仍然指向该端点的 Base URL 和模型环境变量，其他端点保持不动。
   - 更名前发布的插件如果声明 `engines.vibex`，安装时把它当作 `engines.dimo`。其他未知引擎名仍然拒绝。

## English

Dimo 0.5.1 is republished. This build stops an update from deleting session data, and it keeps the workflow, canvas, and timeline changes already in this version.

0.5.0 and the first 0.5.1 build stored the only session database inside the install directory. A macOS in-app update replaces `Dimo.app` and deletes that database before the new version starts. This build keeps the release database outside the app bundle, adopts older copies at startup, and moves any leftover out again before the bundle is replaced.

### Critical fix

1. **Updates no longer delete session data**
   - The release database now lives in the system user directory:
     - Windows: `%APPDATA%\dimo\dimo\data`
     - macOS: `~/Library/Application Support/app.dimo.dimo`
     - Linux: `~/.local/share/dimo`
   - The first launch adopts an install-directory database, an older VibeX directory, and any `*.superseded-*` sibling that still contains `db.sqlite`. The copy with sessions is kept. The other copy is renamed aside and is not deleted.
   - An in-app update moves data out again before replacing the bundle. On macOS, the update stops if a database is still inside the `.app`, and asks you to quit Dimo, open it once, confirm the sessions are there, and then update.
   - A macOS 0.5.0 or 0.5.1 update that already finished cannot restore the copy it deleted. On Windows, a remaining `%LOCALAPPDATA%\Dimo\data\db.sqlite` is adopted the first time this build opens.
   - If your data is still in `Dimo.app/Contents/MacOS/data`, open this build once, or copy that directory out, before you replace `Dimo.app`.

### Features

1. **Workflow Studio: full test, publish, and unnamed-draft protection**
   - The toolbar can run a full test, publish the task, and step the canvas backward or forward. The node inspector can read the current session config.
   - Leaving an unnamed draft ("新建任务" / "New Task") now asks for a name first, so the next visit does not overwrite `~/.dimo/workflows/新建任务.dimo-workflow.json` and drop the graph.
   - Workflow tools mark the definition open on the canvas (`canvasViewing` and `dimo.canvas.viewing`). The shared workflows directory keeps a single unnamed draft.

2. **Grouped multi-provider model menus**
   - Models advertised as `provider/model` (OpenCode, DSH, OMP, and similar agents) collapse into a provider row whose submenu lists only that provider's models. The selected value stays the full id.
   - Claude, Codex, and Grok catalogs without that prefix stay flat. Session settings, new-session creation, and agent defaults share the grouping.

### Improvements

1. **Conversation timeline and user-message lists**
   - Visible virtual rows stack inside one window that scrolls with the transcript. A short height estimate no longer paints a later turn over an earlier one.
   - Assistant virtual-row keys are stable: tools use `tool_use_id`, and markdown or thinking uses a content digest. Inserting a tool ahead of a block keeps the height that was already measured.
   - Turns that do not yet have a sort index land after global side rows instead of sharing that band.
   - CJK ordered markers (`1.`, `1、`, `1）`) and ordered items glued onto one line are normalized into lists the markdown parser accepts.

2. **Infinite canvas, free tabs, and shell navigation**
   - Switching from the canvas back to free tabs opens at most the 10 most recently active nodes.
   - Session-list color slots and canvas node headers use the same order.
   - Shell navigation can sit on the left or the right. Dragging a panel handle, or opening a panel when only one side is occupied, no longer hides the panel in the wrong group. Empty groups close after the drag settles.

3. **Boot theme and paired-phone reminders**
   - The window canvas follows the saved light or dark theme at startup. A light theme no longer inherits a dark system WebView background.
   - The settings window and desktop toasts do not pull the main window forward.
   - An offline reminder for a paired phone stays quiet for 24 hours per device. An in-progress connect request and the short just-connected confirmation are not rate-limited.

4. **Per-launch ACP temp directories**
   - Each ACP session and Antigravity login gets its own `run-<id>` temp directory. When the launch ends, that directory is removed, including any PyInstaller `_MEI*` tree extracted into it.
   - Startup sweeps unlocked leftovers and skips directories that are still locked, owned by a live process, or younger than two minutes. Native Claude and Codex keep a stable temp directory.

### Fixes

1. **Antigravity official login and the ACP session pump**
   - Official login opens the authorization URL returned by `authenticate` instead of leaving `session/new` pending.
   - An oversized or newline-less ACP stdout frame is discarded and the read buffer shrinks, so one giant JSON-RPC frame cannot stay resident for the life of the reader.
   - A slow persist no longer blocks every concurrent session on "generating". High-volume deltas can be shed, and terminal events can still enter the channel. Cancelling the only active prompt emits a finished event with a cancelled stop reason.

2. **DSH provider deletion and pre-rename plugin manifests**
   - Deleting a DSH provider clears the base URL and model environment only when they still point at that endpoint.
   - Plugin packages published before the rename may declare `engines.vibex`. Install treats that key as an alias of `engines.dimo`. Other unknown engine names are still rejected.

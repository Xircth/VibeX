# 工作区生命周期修复与验证

对应 [Orca 对照审查](2026-11-13-vibex-orca-workspace-audit.md)。参考 Orca 提交 `96bad75a6d84eaa0a029be80817f1692700565be` 的仓库 cwd、先准备变更再 setup、删除失败保留记录等行为。

## 实现结果

- 保留默认项目原目录模式：不创建隔离目录，不运行隔离工作区生命周期命令。
- 保留多仓库布局及自定义工作区根目录规则。生命周期命令逐仓库执行，cwd 使用各仓库的 `default_working_dir`；提供容器、仓库与源仓库路径环境变量。
- 初始化先物化仓库，再复制用户选择的未提交更改、环境文件和图片，然后运行命令。目标已有文件受保护；复制失败不再使用 `reset --hard` 或 `clean` 清除用户文件。
- 初始化阶段和逐仓库完成进度持久化。失败保留记录、目录和日志，普通打开不会重跑失败 hook；设置页可以查看输出、明确确认后重试或停止初始化。已完成仓库不会因另一个仓库失败而重复执行。
- 删除在公共容器服务中串行化，检查真实回合、旧进程和终端。命令或物理清理失败保留记录；先删 worktree，再按请求删分支，最后事务删除记录。部分分支已删除时再次删除保持幂等。
- Host 的配置读写和生命周期命令使用实际部署的设置文件。空分支前缀和多段前缀统一接受；无效前缀不会阻挡独立目录设置保存；保存错误可重试，旧响应不会覆盖较新编辑。
- 设置页提供仓库命令目录、环境文件复制规则、隔离工作区列表、初始化状态、输出、重试、停止和删除入口。清理数量明确为提醒阈值。

## 兼容与限制

- 已有完整工作树没有初始化日志时沿用现有目录，不自动补跑可能有副作用的命令。
- 重试仅跳过已记录成功的仓库。失败命令可能已经产生外部副作用，必须检查输出后明确重试。
- 未提交更改要求源和目标基于同一 HEAD；复制中途失败后若目标已有改动会保留并报错，需要检查目标后再恢复。
- 日志完整保存在工作区；状态接口每仓库最多返回末尾 8 KiB。
- 本轮没有启动桌面程序执行 GUI 端到端验收；Host 集成和前端组件测试分别验证真实业务链路与交互。

VibeX vs Codeg 深度对比分析报告
经过全面分析两个项目的设置体系、国际化、路由结构和产品完成度，以下是详细的差距清单：

实施进展（2026-06-12）：

- Phase 0 基线已恢复：`prepare-db` 的 Windows SQLite URL 已修复，SQLx 离线缓存已重生成；`prepare-db:check`、`cargo test --workspace`、前端全量 vitest 均已通过。`CLAUDE.md` / `AGENTS.md` 删除仍按 Phase 0 要求保留为未提交用户态修改。
- 前端会话渲染已完成第一批高优先级收敛：Prism/HTML 注入路径已替换为 Shiki token 渲染；数学公式已通过 `remark-math`、`rehype-katex`、KaTeX 接入；Mermaid 已通过动态导入和 SVG data URL 接入，失败态保留源码，并拆出 `vendor-mermaid` chunk。
- Stick-to-Bottom 与消息虚拟滚动已补齐并完成审查回修：用户贴底时随流式内容增长自动跟随，用户上滚后不抢滚动；会话列表改为真实虚拟 rows，并提供 `scrollToIndex` 给后续导航轨；Shiki 已拆出 `vendor-shiki`，虚拟列表移除全量 `measure()`，补齐 `scrollMargin` 和贴底二次校正。
- 工具卡第一批和 content parts 适配层已落地：命令、文件读写、搜索/web fetch、通用 JSON 已拆为分型卡；`adaptContentParts.ts` 能把 VibeX normalized entries、Phase 3 imported messages、Phase 6 agent events 转为统一 `AdaptedContentPart`。
- 尚未关闭的关键差距：Streamdown 主链路、CJK 专项优化、导航轨、第二批工具卡、TurnStats、图片/生成图片、Composer cmdk、i18n、设置体系扩展、代理、Git 账户/Web Service/Project Boot 等仍需按 `docs/specs/codeg-alignment` 分批推进。

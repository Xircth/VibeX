# Requirements：非 Git 一等项目与项目管理树化

## 1. 假设

1. 桌面端仍是首要交付面；同一套 React UI 也跑在 Host Web。本规格不单独做移动端。
2. 用户日常导入是「一个文件夹 → 一个项目」。底层虽有 `project_repos` 一对多，产品上不再把多仓当作一个项目的运行模型。
3. 树只是管理从属。在项目 A 建会话，工作目录就是 A；切到 B，B 是完整独立项目。
4. 不引入 ADR-0006 的无工作区 scratch 会话。非 Git 项目仍有工作区，工作区就是该目录。
5. 第一期不做无关目录的同级画框成组。路径包含关系的挂树可以做。
6. 视觉权威是仓库根 `DESIGN.md`（macOS Tahoe）。控件组合走现有 shadcn/Radix 封装，不新开一套设计系统。

## 2. 目标

两件必须同时成立：

1. **非 Git 目录是一等项目。** 导入不自动 `git init`。用户可以在该目录下直接建会话、读该目录下的全部文件。
2. **项目管理树化。** Git / 非 Git 都是树节点。导入时发现的直接子 Git 可勾选后作为独立子项目挂上；已导入且路径包含的项目可拖到父节点上。

成功标准：用户选中含有 Git 子目录 B、C 的普通文件夹 A，不把 A 初始化成 Git，仍能在 A 工作；B、C 作为独立项目出现在 A 下，并可单独切换进去工作。

## 3. 功能需求

### PRJ — 项目身份

- **PRJ-001**：项目有 `root_path`（用户选择的目录）。这是文件与会话的根，不再用「至少一个 Git repo」作为项目存在条件。
- **PRJ-002**：Git 是属性，不是入场券。目录是 Git 仓库则该项目具备工作区/分支/Git 操作；否则没有这些能力，但不另写一套会话产品。
- **PRJ-003**：一个 Git 仓只对应一个未隐藏项目。子 Git 不得再登记为父项目的 `project_repos` 行。
- **PRJ-004**：打开已有文件夹时禁止自动 `git init`。提供「将本文件夹初始化为 Git 仓库」，默认不勾选。
- **PRJ-005**：新建空项目仍可初始化为 Git（现有「创建新项目」路径保留，行为不变）。
- **PRJ-006**：非 Git 项目后来执行初始化：原地升级为 Git 项目，出现工作区与完整 Git 能力。若已有 Git 子项目，允许继续，但必须先给出嵌套仓库风险提示。
- **PRJ-007**：再次打开已隐藏项目时，按 `root_path` 匹配，取消隐藏并复用同一项目 id 与会话，不得新建项目。

### IMP — 导入与扫描

- **IMP-001**：导入目录 A 时，只扫描 **A 的直接子目录** 是否含 `.git`（例如 `A/B/.git`、`A/C/.git`）。不递归到 `A/foo/bar/.git`，不进入 `node_modules` 等被忽略目录。
- **IMP-002**：发现的子仓列出供勾选，**默认不勾**。非 Git 的 A 与 Git 的 A 同样处理。
- **IMP-003**：勾选的子仓各自成为独立项目。若这次导入勾选了它们，则 `parent_project_id = A`。
- **IMP-004**：子路径上已有项目则复用，不新建。仅当用户在这次导入中勾选了它，才改 parent。
- **IMP-005**：先导入 B 再导入 A：**不**自动把 B 挂到 A 下。

### TREE — 管理树

- **TREE-001**：`parent_project_id` 单父、无环。隐藏项目不出现在树和最近列表里。
- **TREE-002**：第一期拖拽只允许：Y 的 `root_path` 是 X 的子路径时，把 Y 拖到 X 上，设置 `parent_project_id = X`。无关目录拖放无效果。
- **TREE-003**：从树/列表摘掉 A：A 标记隐藏，磁盘不动，A 的会话与工作区记录保留。直接子项目 `parent_project_id` 清空（升为根）；那些子项目自己的子节点不变。
- **TREE-004**：恢复 A 后，子项目不会自动挂回。需要的话用户再拖。
- **TREE-005**：首页「最近项目」与项目栏都按树展示未隐藏项目。
- **TREE-006**：第一期不做「两个无关目录同级放进一个框、无父节点」。

### SES — 会话与工作区

- **SES-001**：会话工作目录 = 当前项目 `root_path`。树关系不参与运行时。
- **SES-002**：非 Git 项目：工作区即该目录。创建会话不出现选择/新建工作区。
- **SES-003**：非 Git 项目：工作区页左上角不显示 current branch / target branch；会话区不显示 Git Actions。
- **SES-004**：Git 项目：现有工作区、worktree、分支选择保持不变。
- **SES-005**：非 Git 的 Git 面板不能对当前项目做任何 Git 操作。若有 Git 子项目，可在面板中选到该子仓再操作，语义等于在那个子项目打开 Git 面板；**不切换当前项目，不改当前会话 CWD**。
- **SES-006**：Git 面板选子仓时，不把子仓写入父项目的 `project_repos`。

### MIG — 迁移

- **MIG-001**：现有一项目一仓：`root_path` = 该仓路径，`parent_project_id` 空。
- **MIG-002**：现有一项目多仓：若各仓路径有共同父目录，生成或复用该父目录为非 Git 父项目，各仓变为子项目。若路径互不包含且无共同父目录，拆成若干独立根项目。
- **MIG-003**：迁移后不再维持「一项目多仓」作为用户可操作模型。`add_project_repository` 对用户关闭。

### UI — 项目栏

- **UI-001**：项目栏加宽，显示较完整项目名，并以缩进树展示从属。
- **UI-002**：栏内下方三个按钮改为横向排列，放在加宽后项目栏的内部右下。
- **UI-003**：树再深也要能在栏内滚动看完；不截成只显示两个字母。

## 4. 非目标（第一期）

- 无关目录的视觉分组框。
- 任意节点拖成通用树、拖一次自动推演 X–A–Y。
- 把子 Git 同时登记为父项目的 repo。
- ADR-0006 无工作区 scratch 会话。
- 从磁盘删除工程文件。
- 彻底销毁项目记录与会话（现有项目栏删除改为摘树；硬删除若保留，必须是单独、二次确认的入口，本规格不实现）。
- 扫描深度超过直接子目录。
- 为非 Git 重做一套会话/Kanban/文件树。

## 5. 验收场景

1. 选中非 Git 的 A，不勾 init，导入成功，A 下文件在会话中可读。A 没有被 `git init`。
2. A 下有 B、C 两个直接子 Git。列表出现且默认不勾。勾选后 B、C 成为 A 的子项目，各自可切换为完整项目。
3. 先导入 B 再导入 A，B 仍是根。把 B 拖到 A 上（B 在 A 路径内）后 B 成为子节点。
4. 把无关目录 Y 拖到 X 上，树不变。
5. 摘掉 A：A 从列表消失；B 升为根；B 的子仍在 B 下；再打开 A 的同一路径，A 的旧会话还在，B 不会自动挂回。
6. 非 Git 的 A 创建会话时看不到工作区选择、分支条、Git Actions。Git 面板不可操作；有子仓时可选择子仓操作。
7. 在已有子仓的 A 上 init Git：先警告嵌套风险，确认后 A 具备完整 Git 能力。
8. 历史多仓项目打开后变成树，不再出现多仓选择器。

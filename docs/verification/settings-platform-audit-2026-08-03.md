## 缺陷清单与根因

### WS-001 — Web 服务启动命令死锁（P0）

- 现象：`start_web_server` 已成功绑定端口并写入运行时后永不返回，UI 会一直处于
  忙碌状态。
- 稳定复现：随机空闲端口、空 Axum Router、2 秒超时，连续多次均失败。
- 根因：启动函数持有全局 `WEB_SERVICE_RUNTIME` mutex guard 写入 runtime 后，未释放
  guard 就调用 `status_from_runtime`；后者再次等待同一 mutex，形成同任务重入死锁。
- 可证伪预测：只在读取状态前释放 guard，最小复现应立即返回 `running=true`，且停止
  命令可以正常清理任务。

### WS-002 — 生成令牌覆盖未保存编辑（P1，数据丢失）

- 现象：端口改为 `19000` 但尚未保存时点击“生成”，输入框被重置为已保存端口
  `17891`。
- 根因：后端令牌生成只更新持久化 token 并返回完整已保存配置；前端随后用该对象
  同时替换 `config` 与 `draft`，错误丢弃 draft 中与 token 无关的编辑。
- 可证伪预测：持久化基线采用后端返回值，而 draft 仅合并新 token，可保留端口和
  自动启动的未保存值，并继续正确显示 dirty action bar。

### WS-003 — 状态与启停控制重复占两行（P2，简便性）

- 现象：“当前状态”和“服务控制”分成两个设置行，第二行重复解释同一个服务状态。
- 根因：展示事实和改变该事实的操作被建模成两个设置项。
- 修复原则：一个设置事实对应一个行；左侧显示状态/地址，右侧同时放状态文本、刷新、
  打开和启停控制。

### CHAT-001 — 消息渠道对话框缺少完整语义链（P1）

- 现象：对话框打开后 `role=dialog` 没有“新建渠道”可访问名称；关闭时标题仍作为孤立
  内容留在页面 DOM。
- 根因：`DialogHeader`/`DialogTitle` 放在 `DialogContent` 的同级；同时项目自定义
  `Dialog` 不会自动添加 `role=dialog` 或建立 `aria-labelledby`，因此标题、内容与对话框
  容器之间没有可访问关系。
- 可证伪预测：标题和描述移入 `DialogContent`，并显式绑定 dialog role 与标题 ID 后，可由
  `getByRole('dialog', { name: '新建渠道' })` 找到。

### CHAT-002 — 事件过滤器嵌套 button（P2，可访问性）

- 现象：React 报告 `<button>` 不能作为另一个 `<button>` 的后代。
- 根因：整项事件使用 `<button>`，内部又放入基于 Radix button 的 `Checkbox`。
- 修复原则：一项只保留一个交互语义；事件项改为带原生 checkbox 的 label，或只用
  Checkbox 本身处理切换。

### MCP/SKILL-001 — 目标 checkbox 从 uncontrolled 切换到 controlled（P2）

- 现象：创建 MCP 后切入本地详情，以及加载本地 Skill 详情时，React 报 uncontrolled →
  controlled。
- 根因：目标映射尚未由 effect 同步时，`apps[agent]` / `agents[agent]` 是 `undefined`，
  随后变为 boolean。
- 可证伪预测：两处 `checked` 始终归一化为 boolean 后警告消失，目标值仍正确。

### LOG-001 — 日志内容卡片嵌套（P2，简便性）

- 现象：`SettingsSection` 已提供 `settings-card`，日志内容又包一层同名卡片，造成双边框
  与多余层级。
- 根因：页面重复承担了分组容器责任。
- 修复原则：日志内容直接作为 `SettingsSection` 内容渲染，只保留一个分组表面。

## 边界与未破坏用户数据的说明

- macOS 的 Tauri 2 没有官方 WebDriver 支持，因此原生窗口不能用 WebDriver 做自动化
  点击；页面交互使用 jsdom 组件测试，Rust 进程链路使用真实 Tokio/Axum 本地端口测试。
- GitHub 登录/退出、真实 IM 发送、外部 marketplace 安装、恢复备份与清除数据均会改变
  用户或外部状态；本轮通过真实前端调用链 + 隔离 backend boundary 验证参数和状态机，
  未对用户当前账号、配置或数据执行破坏性操作。
- 因而上述外部/破坏性末端不宣称已在当前用户环境完成实操作验收；其证据范围是
  UI → API 契约、工作区后端测试与隔离状态机。真实账号、网络及用户数据环境的最终可用性
  仍需在一次性账号或可丢弃数据目录中验收。
- 设置页全量、完整前端、Rust 工作区、check、变更范围 lint 与桌面启动烟雾验证均已
  完成；仓库级 lint 的基线阻塞已在“修复后执行结果”中单独披露。

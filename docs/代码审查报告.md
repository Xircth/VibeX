## 一、掩盖型 Fallback / 错误吞噬（用户最高关注）

> 共性问题：把"真实错误"悄悄转成"默认值/成功/空"，且**普遍缺失 fallback 分支日志**。最危险的不是崩溃，而是 **"无声错配"**——逻辑跑偏却无任何痕迹，最难排查。

### 1.1 [High] ACP session 查找失败时生成幽灵 session，权限/终端永久错配
- **位置**：[crates/agents/src/manager.rs:1570-1573](crates/agents/src/manager.rs#L1570-L1573)（request_permission）、`:1739-1741`（create_terminal 同模式）
- **证据**：
  ```rust
  let session_id = self.agent_session_for_acp(args.session_id.0.to_string())
      .await.unwrap_or_default();   // 失败 → Default
  ```
- **危害**：已确认 `AgentSessionId::default()` = `Uuid::new_v4()`（[crates/agents/src/ids.rs:12-20](crates/agents/src/ids.rs#L12-L20)）= **全新随机 UUID**，不是 nil。当 ACP 上报的 session 查不到时，权限请求被挂到一个不存在的 session，前端永远收不到、用户无法响应，且**无任何日志**。隐蔽逻辑 bug。
- **建议**：`None` 时 `warn!` 并拒绝/取消该请求，绝不能用随机 default 兜底。

### 1.2 [High] config v5→v6 迁移把未知 executor 静默改写成 ClaudeCode
- **位置**：[crates/services/src/services/config/versions/v6.rs:79-82](crates/services/src/services/config/versions/v6.rs#L79-L82)
- **证据**：`BaseCodingAgent::from_str(&old_coding_agent).unwrap_or(BaseCodingAgent::ClaudeCode)`
- **危害**：对照 [crates/executors/src/executors/profile.rs:89](crates/executors/src/executors/profile.rs#L89) 的 serde 边界正确返回 `custom("unknown executor")`；而迁移路径选择默认 ClaudeCode，用户原配置的 agent 被无声替换，且已先备份原文件（无法感知回滚）。
- **建议**：迁移失败保留原值或 `warn!`，而非默认。

### 1.3 [High] 写真实 CLI 配置时，备份静默失败后仍继续覆盖用户文件
- **位置**：[src-tauri/src/commands/model_provider.rs:558-580](src-tauri/src/commands/model_provider.rs#L558-L580)（`backup_existing` 返回 `()`）、`:547-554`
- **证据**：
  ```rust
  fn backup_existing(path: &Path, agent: &str) {            // 无法上报失败
      if std::fs::create_dir_all(&dir).is_err() { return; } // 建备份目录失败 → 静默放弃
      if std::fs::copy(path, &dest).is_err() { tracing::warn!(...); return; }
  }
  // Windows: if path.exists() { let _ = std::fs::remove_file(path); }  // 删除失败被吞
  ```
- **危害**：`apply → write_rendered → backup_existing` 链中，备份在权限不足/磁盘满时被静默跳过，紧接着覆盖用户真实 CLI 配置（`~/.codex/config.toml` 等），损坏不可逆且用户无感知。
- **建议**：`backup_existing` 返回 `Result`，备份失败时拒绝写入。

### 1.4 [High] git CLI 的 `rebase_onto` 把 merge_base 失败静默退化为 old_base（破坏性）
- **位置**：[crates/git/src/cli.rs:576-583](crates/git/src/cli.rs#L576-L583)
- **证据**：`let merge_base = self.merge_base(...).unwrap_or(old_base.to_string());` 随后 `rebase --onto new_base merge_base task_branch`
- **危害**：merge_base 计算失败时用 `old_base` 当分叉点继续 rebase，可能重放**错误范围的提交**导致丢失/重复 commit，错误被完全掩盖。
- **建议**：merge_base 失败应 `?` 向上传播。

### 1.5 [High] 编辑器 extensions.json 解析失败时用空对象覆盖，抹掉用户全部推荐
- **位置**：[crates/services/src/services/config/editor/mod.rs:208-216](crates/services/src/services/config/editor/mod.rs#L208-L216)
- **证据**：`from_str(&content).unwrap_or_else(|_| json!({"recommendations": []}))` 随后 `to_string_pretty` 写回。
- **危害**：用户 `.vscode/extensions.json` 含注释（JSONC，VSCode 合法）时解析失败，会被空对象覆盖写回，**抹掉用户其他所有推荐扩展**。有破坏性副作用。
- **建议**：解析失败应 `warn!` 并 return（不写回）。

### 1.6 [High] diff 统计把 DB/git 错误悄悄变成 None/0
- **位置**：[crates/services/src/services/diff_stream.rs:50-101](crates/services/src/services/diff_stream.rs#L50-L101)
- **证据**：`...find_repos_...().await.ok()?`（DB 失败→整个统计返回 None）、`Ok(Ok(commit)) => commit, _ => continue`（git 失败→该 repo 跳过，stats 静默偏小）。
- **危害**：`compute_diff_stats` 返回 `Option`，调用方无法区分"真无变更"与"DB/git 出错"，UI 显示 0 改动而非报错。
- **建议**：改返回 `Result`，DB/JoinError 用 `?` 上抛；仅合法的"无 base commit"才 `continue` + warn。

### 1.7 [Medium] 把所有异常当"用户取消"的吞错 fallback（前端）
- **位置**：[frontend/src/components/tasks/Toolbar/GitOperations.tsx:96-98](frontend/src/components/tasks/Toolbar/GitOperations.tsx#L96-L98)、`:283-285`
- **证据**：

- **建议**：区分取消信号（`result.action === 'cancelled'`）与真实错误，后者 `setError(...)`。

## 四、错误处理一致性

### 4.1 [Medium] `AppError` 序列化为纯字符串，前端拿不到机器可读错误码
- **位置**：[src-tauri/src/error.rs:15-39](src-tauri/src/error.rs#L15-L39),76-130
- **危害**：`From<anyhow>`/`From<sqlx>`/多数 service 错误统一压进 `AppError::Internal(e.to_string())`，前端无法编程区分（DB 约束冲突 vs 网络 vs IO 都是一句 Internal 字符串），放大了多处 `format!`-into-string 的危害。
- **建议**：给 `AppError` 增 `code` 字段，序列化为 `{ kind, message, code }`。

### 4.2 [Medium] model_provider 上游 5xx 被错误归类为 BadRequest + 错误体丢失
- **位置**：[src-tauri/src/commands/model_provider.rs:803](src-tauri/src/commands/model_provider.rs#L803)（`expect("toml table")`）、`:1303-1312`
- **危害**：上游服务端错误被标成客户端错误；用户手改坏 config.toml（根非 table）会让命令 panic；同文件 render_hermes 已正确用 `ok_or_else` 而 render_codex 用 `expect`，风格不一致。
- **建议**：上游 5xx 用 `Internal`；Codex 分支对齐 Hermes 的 `ok_or_else`。

### 5.1 [High] 事件溯源投影每次全量重放，无快照/增量（读放大根因）
- **位置**：[crates/db/src/models/conversation_projection.rs:218-221](crates/db/src/models/conversation_projection.rs#L218-L221)、分页 [src-tauri/src/commands/conversations.rs:273-285](src-tauri/src/commands/conversations.rs#L273-L285)
- **危害**：`conversation_detail`/timeline 每次从 `sequence>0` 拉**全量事件** fold 并逐条 `serde_json::from_str`，复杂度 O(总事件数)，**对话越久越慢**；分页是"先全量投影再内存 skip/take"，翻第 N 页与第 1 页成本相同。
- **建议**：引入投影快照表（持久化 `last_sequence` + 折叠结果），改为"读快照 + 仅重放 `events_since(snapshot_seq)`"；或在内存 `ConversationRuntimeState` 缓存已折叠投影。

### 5.2 [High] 事件流：全局单通道无差别 IPC 全推 + 每订阅者反序列化过滤 + 每次进程更新重算 workspace
- **位置**：[src-tauri/src/events.rs:105-117](src-tauri/src/events.rs#L105-L117)、[crates/services/src/services/events/streams.rs:54-104](crates/services/src/services/events/streams.rs#L54-L104)、[crates/services/src/services/events.rs:251-277](crates/services/src/services/events.rs#L251-L277)
- **危害**：所有 DB 变更经一个全局通道无过滤 IPC 序列化推到前端，又被 per-subscriber stream 重复消费（**双扇出**）；N 个订阅各自对每条 patch 做整行 `serde_json::from_value` 判归属（复杂度 = 订阅数 × 消息数）；每次 `ExecutionProcess` UPDATE 都触发 `find_by_id_with_status`（含 2 个 EXISTS 子查询）重算整 workspace 状态并广播（代码注释自承会 starve git-status / "database is locked"）。并发 workspace 多时最先暴露。
- **建议**：patch 路径里编码 session_id/project_id 或按 topic 分通道（过滤只比对路径字符串）；`push_workspace_update_for_session` 去抖，仅在进程 status 跨阈值时重算广播。

### 5.3 [High] 前端流式更新触发全量重算 + 整快照深拷贝
- **位置**：[frontend/src/features/conversation/conversationStore.ts:133-157](frontend/src/features/conversation/conversationStore.ts#L133-L157)、[frontend/src/utils/streamJsonPatchEntries.ts:64-72](frontend/src/utils/streamJsonPatchEntries.ts#L64-L72)（`structuredClone(snapshot)`）、`VirtualizedList.tsx:453-476`（`buildDisplayEntries` 全量重跑）+ `DisplayConversationEntry.tsx:73`（无 `React.memo`）
- **危害**：每条 `assistant_text_delta` 走 `rows.map()` 重建整数组 + 一串 O(n) 派生 useMemo 全部重算；执行进程路径每帧 `structuredClone` 整个 entries（数百上千条含完整 content/diff）；可见行每次重渲染都重跑正则净化。长会话流式期间每秒数十次 O(n) 计算。
- **建议**：reducer 只替换被改 turn 复用其余引用；执行进程路径加 16-32ms 合批 + 浅拷贝 + 结构共享；给 `DisplayConversationEntry` 加 `React.memo` + 按 content 缓存正则结果。

### 5.4 [High] 文件搜索高频路径同步 git2 + 整仓遍历阻塞 tokio worker
- **位置**：[crates/services/src/services/file_search.rs:147-149](crates/services/src/services/file_search.rs#L147-L149)（缓存命中也每次同步 `get_head_info`）、`:300-393`（fallback 在 async fn 内同步遍历整仓 + 逐项 stat）
- **危害**：文件搜索是边打字边搜的高频路径，即使命中缓存每次都在 tokio worker 上同步磁盘 IO；缓存未命中时同步走遍整仓，大型 monorepo 单次几十到几百毫秒占住 worker。
- **建议**：两处均包进 `spawn_blocking`（同 `file_ranker::compute_stats` 已正确的模式）。

### 5.5 [High] 文件树完全无虚拟化，递归 `.map()` 渲染全部节点
- **位置**：[frontend/src/components/file-tree/FileTreePanel.tsx:1262](frontend/src/components/file-tree/FileTreePanel.tsx#L1262),1381,1518
- **危害**：展开后一次性渲染全部节点（中大仓库上千 button+FileIcon DOM）；`renderNode` 是内联递归闭包，任意本地 state（预览/拖拽/右键）变化整树重渲染。文件树面板卡顿主因。
- **建议**：拍平可见节点为线性列表后用 `@tanstack/react-virtual`；节点行抽 `memo` 子组件。

1. **掩盖型 fallback（用户最关注，且最难排查）**：优先修 1.1 幽灵 session、1.2/1.3 配置静默改写/备份失败仍覆盖、1.4 rebase 退化、1.5 extensions 覆盖——这些会造成"无声错配"或破坏性副作用。统一原则：fallback 分支必须 `warn!`，破坏性操作前置校验失败必须显式失败。

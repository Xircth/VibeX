# VibeX 安全审查报告

> 审查日期：2026-06-18 ｜ 审查方式：只读静态审计（未运行/未修改代码）
> 审查范围：Rust 后端核心 crates + Tauri IPC 命令面 + 前端渲染 + 凭据管理 + 多 agent 委派子系统
> 代码规模：Rust ≈ 9 万行，前端 ≈ 5.4 万行 / 786 文件

## 综合评分

| 子维度 | 评分 | 说明 |
|---|---|---|
| 核心执行路径（git/spawn/SQL/TLS/unsafe） | **7.0** | 杜绝经典命令注入与注入类高危，工程质量优秀 |
| CSP / 内容安全 | **2.0** | `csp: null` 且无 meta 兜底 |
| 能力/权限最小化 | **3.0** | fs `**` 全盘读写 + shell open 默认全开 |
| IPC 输入校验 / 沙箱 | **4.0** | 有路径穿越防护，但通用 FS 命令无 workspace 沙箱 |
| 凭据管理 | **3.0** | API key 明文落盘 + 备份残留，无文件权限收紧 |
| XSS / 内容注入 | **7.0** | 主渲染链路（react-markdown / DOMPurify / escapeHtml）处理得当 |
| 委派/信任边界 | **5.0** | token+depth 鉴权链完整，但 socket 无权限 + working_dir 无边界 |
| **安全性总分** | **5.5 / 10** | 核心硬、外壳软：本地单用户可控，多用户/恶意 agent 场景可被利用 |

**一句话结论**：VibeX 的"内功"（外部进程执行、git、SQL、TLS）做得相当好，几乎封堵了所有经典注入类高危；但"外壳"（Tauri 能力配置、IPC 文件命令、凭据落盘）采取了**完全信任本机前端**的姿态，在多用户主机、被攻陷/恶意 agent、内容注入链路下存在可利用的攻击面。优先级最高的修复是 **CSP + fs 收窄 + 凭据加固** 三项。

## 一、High 级别发现

### H-1. CSP 完全禁用（`csp: null`）
- **类别**：CSP / 内容安全
- **位置**：[src-tauri/tauri.conf.json:24-26](src-tauri/tauri.conf.json#L24-L26)、[src-tauri/tauri.dev.generated.conf.json:24-26](src-tauri/tauri.dev.generated.conf.json#L24-L26)
- **证据**：`"security": { "csp": null }`；前端 `index.html` 也无 CSP meta。
- **影响**：这是一个会渲染 **AI 模型输出 + 外部 IM 消息** 的应用。一旦任意一处出现 DOM 注入（见 H-2、M-2），没有任何 CSP 兜底来阻止内联脚本执行、外连 C2、加载远程脚本。CSP 缺失把"小注入"放大成"任意脚本执行"。
- **建议**：设置严格 CSP，例如：
  `default-src 'self'; script-src 'self'; connect-src 'self' ipc: http://ipc.localhost; img-src 'self' asset: data: blob:; style-src 'self' 'unsafe-inline'`，通过 Tauri 的 CSP 占位符注入 nonce/hash，禁止 `script-src 'unsafe-inline'/'unsafe-eval'`。

### H-2. 文件系统能力对全盘 `**` 开放读写
- **类别**：能力/权限
- **位置**：[src-tauri/capabilities/default.json:10-17](src-tauri/capabilities/default.json#L10-L17)、[src-tauri/tauri.conf.json:43-45](src-tauri/tauri.conf.json#L43-L45)
- **证据**：`fs:allow-read` / `fs:allow-write` 的 `allow` 均为 `[{ "path": "**" }]`，且 `requireLiteralLeadingDot: false` 使 `**` 还能匹配 dotfile（`~/.ssh`、`~/.aws`、`.env`）。
- **影响**：前端 JS（含被注入脚本）可经 `@tauri-apps/plugin-fs` 直接读写任意路径，**无需经过任何后端命令**。叠加 H-1（无 CSP）= 任意本地文件读写。
- **建议**：把 fs scope 收窄到实际需要的目录（项目根、worktree、应用数据目录），其余文件操作只走经过校验的自定义命令；恢复 `requireLiteralLeadingDot` 默认值以挡 dotfile。

### H-3. API key 与凭据明文落盘 + 备份残留旧密钥，无文件权限保护
- **类别**：凭据
- **位置**：
  - secrets 明文写入：[src-tauri/src/commands/model_provider.rs:255-272](src-tauri/src/commands/model_provider.rs#L255-L272)
  - 渲染进真实 CLI 配置：`render_claude`（写 `ANTHROPIC_AUTH_TOKEN`）、`render_codex`（`OPENAI_API_KEY`）、openclaw `apiKey`、hermes `api_key`（[同文件:530-1175](src-tauri/src/commands/model_provider.rs#L530-L1175)）
  - 明文备份轮转：[src-tauri/src/commands/model_provider.rs:558-579](src-tauri/src/commands/model_provider.rs#L558-L579)
  - web_service token 明文落盘：[src-tauri/src/commands/web_service.rs:106-127](src-tauri/src/commands/web_service.rs#L106-L127)
- **证据**：`tokio::fs::write(&path, content)`（无 `set_permissions`），密钥以纯 JSON/TOML 明文存于 `asset_dir()/model-provider-secrets.json`、各 agent 真实 CLI 配置文件、`~/.vibex/provider-backups/<agent>/*.bak`（最多保留 10 份）。
- **影响**：同机其他本地用户/进程（或经 H-2 的全盘 fs 链路）可读取全部 provider 的 API key；轮换/删除 key 后旧值仍以明文滞留在备份中。
- **建议**：优先存系统钥匙串（macOS Keychain / Windows Credential Manager / libsecret）；若必须落盘则写入后统一 `chmod 600` + Windows ACL 仅当前用户；删除 key 时一并清理备份，或对备份做密钥脱敏。

### H-4. 通用 FS/进程 IPC 命令盲信前端绝对路径，无 workspace 沙箱
- **类别**：IPC 校验
- **位置**：[src-tauri/src/commands/file_tree.rs:272-377](src-tauri/src/commands/file_tree.rs#L272-L377)（`read_file_content`/`save_file_content`/`delete_file`/`read_binary_asset`/`move_item`/`create_directory`/`copy_item`/`trash_item`）、[src-tauri/src/commands/filesystem.rs:54-105](src-tauri/src/commands/filesystem.rs#L54-L105)
- **证据**：这些命令仅做 `sanitize_file_path`（拒 `..`、要求绝对路径、canonicalize），**未把路径限制在任何 workspace/项目根内**：
  ```rust
  pub async fn save_file_content(path: String, content: String) -> Result<(), AppError> {
      save_file_content_at_path(&path, &content)  // 任意绝对路径可写
  }
  ```
- **影响**：前端（或注入脚本 / 被诱导的 AI 工具调用经前端转发）可读/写/删/移动任意文件，如覆写 `~/.bashrc`、读 `~/.ssh/id_rsa`。`sanitize_file_path` 只防穿越字符串，不防"直接给绝对敏感路径"。
- **建议**：给这些命令传入 `workspace_id` 并强制 canonical 路径 `starts_with(workspace_root)`；全局配置类读取用专门的白名单命令而非通用 `read_file_content`。

### H-5. `open_github_cli_login` 把未校验的 `host` 拼进 shell — 命令注入
- **类别**：命令注入
- **位置**：数据流 [src-tauri/src/commands/version_control.rs:272](src-tauri/src/commands/version_control.rs#L272) → sink `:335`(Windows)/`:343-344`(macOS)/`:354,358`(Linux)
- **证据**：
  ```rust
  // host 来自前端，仅 trim/非空过滤
  let command = format!("gh auth login --web --git-protocol https --hostname {host}");
  spawn_visible_terminal(&command) // Windows: cmd /C start "" cmd /K {command}
  ```
- **影响**：`host`（GitHub Enterprise 主机输入框）未做字符校验即拼成完整命令行。Windows 经 `cmd /K`、Linux 经 `sh -lc`（完全不转义），`host` 含 `&`/`|`/`&&`（如 `github.example.com & calc`）即可注入任意命令。
- **建议**：对 `host` 严格白名单（仅 `[A-Za-z0-9.-]`，拒绝元字符）；sink 端改用参数数组 `Command::new("gh").args([...,"--hostname",host])` 而非交整条命令行给 shell。

### H-6. 委派 `working_dir` 完全由 agent 输入控制，无路径边界校验 — 隔离逃逸
- **类别**：路径穿越 / 信任边界
- **位置**：[crates/delegation/src/listener.rs:124-133](crates/delegation/src/listener.rs#L124-L133)、[src-tauri/src/delegation/spawner.rs:51-53](src-tauri/src/delegation/spawner.rs#L51-L53)、落地 [crates/agents/src/manager.rs:741](crates/agents/src/manager.rs#L741)
- **证据**：
  ```rust
  // 仅 trim/非空，无 canonicalize、无 workspace 前缀校验
  let requested_working_dir = req.input.get("working_dir").and_then(Value::as_str)
      .map(str::trim).filter(|dir| !dir.is_empty()).map(str::to_string);
  ```
- **影响**：VibeX 的核心安全属性是"每个 workspace 在 git-worktree 中隔离"。一个被攻陷/恶意的父 agent 可 `delegate_to_agent({working_dir: "C:\\Users\\..."})` 在隔离边界外任意目录启动子 agent 读写文件，**绕过 worktree 隔离**。叠加 M-1（Yolo 继承）可放大为无人值守的任意目录操作。
- **建议**：对 `requested_working_dir` 做 canonicalize 后强制校验其落在父连接 workspace 根目录之内，越界拒绝。

### H-7. 委派 socket / 命名管道无权限保护 — 本机跨用户信任边界缺口
- **类别**：鉴权 / 信任边界
- **位置**：[crates/delegation/src/listener.rs:167-187](crates/delegation/src/listener.rs#L167-L187)（UDS）、`:227-229`（`$TMPDIR` 下路径）、`:192-220`（Windows 命名管道无显式 DACL）
- **证据**：`UnixListener::bind(&socket_path)` 后直接 `accept`，无 `set_permissions(0o600)` / `SO_PEERCRED` 校验（全仓零命中）；socket 落在共享 `$TMPDIR`（`vibex-delegation-<pid>.sock`）。
- **影响**：默认 umask（022）下组/其他用户可连接 socket；虽无 token 无法发起委派，但存在探测/DoS（占 accept、发 16MB 帧），并与 M-2（argv token 泄露）组合成跨用户冒充链路。
- **建议**：bind 后立即 `set_permissions(0o600)` 或放入 `0o700` per-user 子目录；理想再用 `SO_PEERCRED`(Linux)/`getpeereid`(macOS) 校验对端 UID；Windows 命名管道设显式 DACL。

## 二、Medium 级别发现

### M-1. 委派子 agent 静默继承全局 auto-approve（含 Yolo）
- **类别**：鉴权 / 危险默认
- **位置**：[src-tauri/src/delegation/spawner.rs:54-66](src-tauri/src/delegation/spawner.rs#L54-L66)；决策 [crates/agents/src/permissions.rs:76-98](crates/agents/src/permissions.rs#L76-L98)
- **影响**：委派出的子 agent 自动复用该 agent 类型的全局 `auto_approve_mode`。若用户对该类型设了 Yolo，子 agent 在（H-6 可任意指定的）目录中执行命令/写文件完全不弹窗，把"给某 agent 开 Yolo"扩散到它能 spawn 的所有子 agent。
- **建议**：委派子会话使用更保守策略（不自动继承 Yolo），或将子 agent auto-approve 纳入显式确认。

### M-2. 委派 token 以明文命令行 argv 传给 MCP companion
- **类别**：密钥 / 鉴权
- **位置**：[src-tauri/src/delegation/inject.rs:45-54](src-tauri/src/delegation/inject.rs#L45-L54)、[crates/vibex-mcp/src/main.rs:312-322](crates/vibex-mcp/src/main.rs#L312-L322)
- **影响**：token 作为 `--token` 命令行参数注入子进程，多用户主机上其他用户可经 `ps`/`/proc/<pid>/cmdline` 读到，结合 H-7 无权限 socket 可冒充父连接发起委派。
- **建议**：token 改用环境变量或 stdin/临时文件传递。

### M-3. 子进程未做环境隔离（缺 `env_clear`），父进程环境全量透传
- **类别**：密钥 / 进程权限
- **位置**：[crates/agents/src/manager.rs:743-745](crates/agents/src/manager.rs#L743-L745)、[crates/agents/src/terminal.rs:131-133](crates/agents/src/terminal.rs#L131-L133)、[crates/executors/src/env.rs:135-137](crates/executors/src/env.rs#L135-L137)（全仓 0 处 `env_clear`）
- **影响**：所有被拉起的 agent CLI / 终端子进程继承 VibeX 进程的全部环境变量，宿主敏感变量会暴露给（半可信的）子进程。属纵深防御缺口。
- **建议**：对 agent/terminal 子进程采用显式 env 白名单（先 `env_clear()` 再注入 PATH + 必要项）。

### M-4. `shell open` 接收 AI / 外部内容生成的 URL，scope 默认全开
- **类别**：能力 / 社工面
- **位置**：[src-tauri/capabilities/default.json:7](src-tauri/capabilities/default.json#L7)、[src-tauri/tauri.conf.json:40-42](src-tauri/tauri.conf.json#L40-L42)、[frontend/src/components/NormalizedConversation/Markdown.tsx:544-549](frontend/src/components/NormalizedConversation/Markdown.tsx#L544-L549)
- **影响**：用户点击 AI 回复 / 他人 IM 消息里的 markdown 链接，会用系统默认程序打开（钓鱼/下载页），且不区分可信（应用自身）与不可信（AI/聊天）来源。
- **建议**：用显式 `shell.open` 正则把协议限制为 `^https?://`；对不可信链接在 UI 上做"即将打开外部链接 + 显示完整 URL"确认。

### M-5. `dangerouslySetInnerHTML` 注入文件图标 SVG，无 CSP 兜底
- **类别**：XSS
- **位置**：[frontend/src/components/FileIcon.tsx:63](frontend/src/components/FileIcon.tsx#L63)
- **影响**：当前 `getFileIconSvg` 若确为静态常量则风险低；但这是"未净化 innerHTML"硬编码模式，一旦图标映射将来掺入文件名/用户数据即成 XSS，且因 H-1（CSP=null）无兜底。
- **建议**：改用 React 组件 / `<use>` 引用静态 sprite，或对 SVG 走 `DOMPurify(USE_PROFILES:{svg:true})`。

### M-6. web_service token 明文存盘且服务本身不鉴权
- **类别**：凭据
- **位置**：[src-tauri/src/commands/web_service.rs:106-149](src-tauri/src/commands/web_service.rs#L106-L149)、`generate_web_service_token:269-273`
- **影响**：当前服务仅暴露 health 且绑定 `127.0.0.1`（良好），但 token 明文落盘 + `router()` 完全不校验 token，说明"受保护接口"尚未实现，未来扩展易遗漏鉴权；前端还提供一键复制明文 token。
- **建议**：token 哈希存储或入钥匙串；为后续接口预置 `Authorization` 中间件并默认拒绝。

## 四、已正确实现（核实无误，避免误报）

为客观起见，列出经核实安全到位的关键点：

- **外部进程执行无 shell 注入**：[crates/git/src/cli.rs:1139](crates/git/src/cli.rs#L1139) `git_impl` 全程参数数组、无 shell；executor 经 `winsplit`/`shlex` 解析成参数数组；ACP agent/terminal/PTY 均参数数组传递。
- **路径处理扎实**：worktree/workspace 目录名经 `git_branch_id` 正则净化；`validate_worktree_target`、`validate_workspace_container_path`、`validate_skill_id`、图片 `sanitize_filename` 均到位。
- **委派鉴权链完整**：传输为 UDS/命名管道（非 TCP，无 `0.0.0.0`）；per-launch token + parent_connection_id 绑定校验；agent_type 经白名单（不接受任意命令）；深度限制真实生效；帧大小 16MB 上限防 OOM；ACP permission 由主进程侧决定，agent 无法自带"已批准"绕过。
- **TLS**：全仓 0 处 `danger_accept_invalid_certs`；crypto provider 在 [src-tauri/src/lib.rs:17-21](src-tauri/src/lib.rs#L17-L21) 最早安装，reqwest 用 no-provider，惰性 client 首次访问晚于安装。
- **SQL**：`crates/db` 及 `local-deployment` 全部 `?`/`$1` 参数绑定，无 `format!` 拼接 SQL。
- **`unsafe`（5 处均合理）**：`git2 set_verify_owner_validation`（Once 守护）、`from_raw_fd/handle`（标准 FFI）、`set_var("PATH")`（启动早期）、`ExpandEnvironmentStringsW`（缓冲处理正确），均有 SAFETY 说明。
- **主 XSS 链路安全**：对话 markdown 未启用 `rehype-raw`（不渲染原始 HTML）、`markdownUrlTransform` 走 `defaultUrlTransform` 挡 `javascript:`；composer 内容经 `escapeHtml` 转义；额外窗口仅加载内部 App 路由。
- **日志泄露未发现**：未发现 api_key/token/secret 的值进入日志宏。

## 五、优先修复路线

最现实的利用链是 **"跨用户冒充 + 隔离逃逸"**（H-7 socket 无权限 + M-2 token argv 泄露 + H-6 working_dir 无边界 + M-1 Yolo 继承）和 **"内容注入放大"**（H-1 CSP=null + H-2 fs 全盘 + M-5 innerHTML）。建议顺序：

1. **P0（结构性，投入产出最高）**：H-1 设置严格 CSP + H-2 收窄 fs scope + H-3 凭据加固（钥匙串或 0600）。
2. **P0（隔离模型，本产品立足之本）**：H-6 working_dir 边界校验 + H-7 socket 权限 + M-2 token 改环境变量。

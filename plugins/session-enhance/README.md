# 会话增强

让当前对话里的 Agent 能向你提问、读取你中途写下的纠偏、查询你点名的其它会话，以及在本会话或其子会话上发送输入、取消回合或等待结束。

这些工具由 VibeX Host 提供，不是某个 Agent 自带的。启用插件后，Host 只把它们注入**之后新开或重新绑定**的 Agent 会话。已经在跑的会话不会热插这份 MCP。

## 启用

这是随 Host 分发的内置插件，默认关闭，不能卸载。在「插件」里打开。内部四个开关默认全开，可单独关掉某一项；关掉的工具不会出现在新会话的工具清单里。

禁用插件后，新会话不再注入 `vibex-session-mcp`。已经注入的会话会把工具留到该会话结束。

## 四个能力

**实时反馈。** 回合进行中，Composer 的「纠偏」会把备注交给当前回合（Agent 支持立刻注入时立即生效，否则等 Agent 下次调用 `check_user_feedback`）。Agent 应在动手前和每个阶段后检查。没有新备注时继续工作，而不是停住空转。

**向用户提问。** 只有真正需要你做决定时才用 `ask_user_question`。调用会阻塞，直到你在界面里作答。不要用它来确认已经能从上下文看出来的事。

**获取会话信息。** 你用 `@` 插入会话链接点名另一段对话时，Agent 用 `get_session_info` 只读查看那次会话的标题、Agent、工作区、分支和最近消息。它不能凭这段查询去改那次会话。

**会话控制。** `send_session_input`、`cancel_session_turn`、`wait_for_session` 只作用于本会话或其子孙。不要拿它们去操作无关会话。

## 配置

四个开关都在本页，默认开启：

- 实时反馈
- 向用户提问
- 获取会话信息
- 会话控制

保存后写入这个插件的 `config.json`。只影响之后新开或重新绑定的会话，不改写已经注入的工具清单。

## 离线与范围

工具走本机 Host。不把会话内容发到插件自己的外部服务。能否上网取决于当前 Agent 和项目策略。

## 排障

- Agent 说没有这些工具：确认插件已启用、对应开关已打开，然后新开或重新绑定会话。
- 提问没有弹出：看「向用户提问」是否关闭；已有会话需要重新绑定。
- 写了纠偏但 Agent 没读到：确认「实时反馈」打开，当前会话已重新绑定，且 Agent 有在阶段边界调用 `check_user_feedback`。Composer 上方会显示等待/已读。
- 关掉插件后旧会话仍能提问：这是预期。工具清单跟会话走，新会话才不再注入。
